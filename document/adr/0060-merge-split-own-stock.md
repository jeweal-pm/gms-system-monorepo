## Context

The owner wants a page like Load to Stock that **Merges** or **Splits** our own stock (`inventory.stock` rows created by Load to Stock). It has one source button, **From Stock**, listing own stock only. Split turns one stock into N ≥ 2 new stocks; Merge turns N ≥ 2 stocks into one new stock. Every result gets a new Stock ID.

What exists today: the auth leaf `merge-split`, the `Menu` type value, the approval type `merge-split` (inventory `approval_setting` + check), and Document Setup key `merge-split` (code **MS**). There are no tables, routes, ledger kinds or page. Stock IDs are issued only by api-master (`issueStockIds`, one counter shared with Memo Receive and Load to Stock). The `consumed` bucket on `stock` was reserved for this kind of conversion (ADR-0052 "used" rule).

## Decision

- **D1 Placement:** module `backend-api-inventory/src/modules/merge-split/`, built like Stock Adjustment / Sale. Stock moves only through a new helper `src/modules/stock/convert.ts`. No new service or container.
- **D2 Document:** `inventory.merge_split` (header, `mode` SPLIT | MERGE, one mode per document), `merge_split_source` (picked stock + snapshot of its on hand), `merge_split_result` (new stock details) and `merge_split_result_photo`. Statuses are those of ADR-0050 plus soft delete; there is no separate CANCELLED status (Q-MS-14).
- **D3 Conservation (Q-MS-04):** each source is consumed **whole**: take = its on hand at pick time = its on hand at apply (stale guard). Split: ≥ 2 results per source, Σ result pcs and weight = take exactly. Merge: 2–200 sources, exactly one result with Σ pcs and Σ weight. No remainder stays on a source, so a source ends with on hand 0 and leaves every picker.
- **D4 Availability (Q-MS-02):** only the `on_hand` bucket is usable. Reserved, Memo Out, sold and consumed quantities stay on the source and are never touched. Draft documents hold nothing; a stock on another **Pending** Merge/Split is hidden from the picker and refused at submit (Q-MS-15). At apply the stocks are locked `FOR UPDATE ORDER BY id` and re-checked; any change returns `409 MERGE_SPLIT_STOCK_CHANGED`. A stock whose load is SYNCING returns `409 MERGE_SPLIT_BUSY`.
- **D5 Cost (company currency):** source take cost = basis × `unit_cost_base` (basis = weight for PER_CT, pcs for PER_PCS; 2 dp half-up; the Load `sourceAmount` rule). **Split:** each result keeps the source unit cost and price unit; result cost = its basis × unit cost; the **last** result of the source absorbs the rounding residue so Σ = take cost. **Merge:** cost = Σ take costs; price unit PER_CT unless every source is PER_PCS; unit cost = cost ÷ basis (4 dp, 0 if basis 0). The server computes all cost; client values are ignored.
- **D6 New stock rows:** details (stone code/attributes, grading, cer, lot, location, stock and sale price, note, photos) are editable (Q-MS-06/10/11) and validated through the existing master `master-data/resolve` and Location Master names. Inherited, not editable: `currency_code` (Merge sources must share one, else 422), `vendor_id`/name, `load_id`, `ref_doc_date`, `ref_doc_no` from the source (Split) or the **oldest** source by `(ref_doc_date, stock_id)` (Merge), so FIFO age and the Load link stay valid. `lot_key`, `card_key`, `item_key` are generated by PostgreSQL. Photos are relinks of existing `stored_file` ids or new uploads under `files/merge-split/` through `@gms/storage`.
- **D7 Stock IDs:** a new master internal endpoint `POST /internal/v1/inventory/stock-ids/issue` issues N IDs from the shared counter (`issueStockIds`), idempotent on `(documentType, documentId, applySeq)` through a new table `partner.inventory_stock_id_issue`. Inventory calls it **before** the apply transaction (no HTTP inside a transaction). A failed transaction retries with the same key and gets the same IDs; a document abandoned after issue leaves a gap, which is allowed (IDs are never reused).
- **D8 Effect**, in one transaction (Save with approval OFF, or Approve):
  1. Lock the document (version) and the source stocks in id order.
  2. Check ACTIVE, own, not SYNCING, on hand = snapshot.
  3. One set-based UPDATE on the sources: `on_hand -= take`, `consumed += take`, `first_used_at` set, `version + 1`.
  4. Insert the result stocks, their photos and movements in bulk.
  5. Store `stock_uuid`, `stock_id`, `applied_version` on each result.
- **D9 Ledger kinds:** `SPLIT_OUT`, `SPLIT_IN`, `SPLIT_REVERSAL`, `MERGE_OUT`, `MERGE_IN`, `MERGE_REVERSAL`. OUT rows are negative on each source with `cost_delta_base = −take cost`; IN rows are positive on each result with its cost; Σ cost per document = 0. Reversals negate them.
- **D10 Reports:** `CARD_KINDS` gains the six kinds (document type `merge-split`, MOVEMENT); `DOCUMENT_TYPES` gains `merge-split` (label "Merge/Split", Stock ID visible, new source `MERGE_SPLIT` that reads doc date/number from `merge_split`). Merge/Split never changes an existing stock's location, lot or attributes; new values exist only on new rows. A movement's card therefore stays the card of its own stock row, and **no card key column on `stock_movement` is needed** (this satisfies ADR-0056 D11 / BE-SC-102). When source and result share a card, the document nets to 0 and the card drops the row; otherwise the source card shows OUT and the result card shows IN. Stock Value is unchanged in code: on hand moves from source cards to result cards and total value is conserved.
- **D11 Reversal ("untouched"):** delete of an effective document, or edit of an auto-approved one, is allowed only if every result stock is ACTIVE and still has `version = applied_version` (so nothing reserved, memo-out, sold, adjusted, re-converted or edited it). Otherwise `409 MERGE_SPLIT_IN_USE {stockIds}`. Reverse writes `*_REVERSAL`, sets results to REVERSED (on hand 0; their Stock IDs stay retired) and returns `take` from `consumed` to `on_hand` on the sources. Edit then re-applies with new Stock IDs (`applySeq + 1`). Sources are always reversible because their `consumed` share can't leave by any other path.
- **D12 Re-conversion (Q-MS-16):** a result is an ordinary own stock; it can be merged or split by a later document once its document is Approved. While the result exists, its source is "used", so the source Load can't be edited or deleted (ADR-0052 rule, `on_hand <> pcs`).
- **D13 Approval and numbering:** the existing type `merge-split` joins `/approval/summary` and `/approval/pending`; numbering key `merge-split` is added to master `INVENTORY_NUMBERING_KEYS` and inventory `NumberingKey`. No auth change: the leaf exists with VIEW/ADD/EDIT/DELETE/APPROVE.
- **D14 Bounds:** ≤ 200 sources and ≤ 200 results per document; ≤ 5 photos per result; JSON ≤ 256 KiB; picker pages ≤ 50 in one statement; a fixed number of statements per apply/reverse (≈ 10) under the existing `WRITE_TX` timeout; three bounded master calls before the transaction.

## Alternatives

- **Update a source in place (Merge into the first stock / Split keeps a remainder):** fewer Stock IDs, but it rewrites an existing stock's card and cost history and needs a card key on movements. Rejected for revision 1 (Q-MS-04 default).
- **Issue Stock IDs from an inventory-local counter:** would collide with the master counter shared by Memo Receive and Load. Rejected.
- **One kind pair `MERGE_SPLIT_OUT/IN`:** `MERGE_SPLIT_OUT_REVERSAL` exceeds `kind VARCHAR(20)` and loses the mode on Stock Card. Rejected.
- **Hold stock while Draft:** blocks sales during editing; the Pending-only exclusion plus the apply-time guard is enough (Q-MS-15).
- **Edit an effective document in place (keep result Stock IDs):** needs per-row delta kinds; reverse + re-apply is simpler. Can be revisited (SQ-MS-03).

## Consequences and capacity

- Inventory migration `20261127100000_merge_split`: 4 tables, the six kinds in `stock_movement_kind_check`, grants; no change to `stock` columns, no backfill. Master migration `20261127100000_inventory_stock_id_issue`: 1 table. Rollback: drop the new tables and restore the previous check list while no `SPLIT_*`/`MERGE_*` rows exist.
- An apply of 200 rows is one short transaction with row locks on ≤ 200 stocks. Picker reads use the existing open-stock partial index plus a new `merge_split_source(stock_uuid)` index. No cache, job, worker or container is added, which fits the 4 GB / 2 vCPU host.
- Approve Center gains a Merge/Split panel; Approval Setup's turn-OFF guard now counts real documents.
