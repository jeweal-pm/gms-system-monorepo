# 2026-11-03 decimal-setup frontend (FE-DEC-101…105, tests of FE-DEC-106)

- Decimal Setup page now uses the real API (`decimalSetup.get` / `save`). The rev 1 browser mock is gone, and the old `gms.decimal-setup.v1` browser value is deleted on load and never read (Q-DEC-17). Save sends the loaded `expectedVersion` and stays off until a value changes. A 409 shows "Someone else changed the decimal setup. Reload to see the latest values." with Reload, and the draft is kept until Reload. "Last updated dd/mm/yyyy HH:mm" (Asia/Bangkok) is shown after the first user save.
- Gate: the page and the Setup tile use the new `decimal-setup` leaf (VIEW to open, EDIT for Edit/Save). `decimal-setup` is in `SETUP_MENU_KEYS`.
- Whole website: new `frontend/src/lib/number-format.ts` does exact half-up formatting with grouping. `DecimalSetupProvider` / `useNumberFormat()` is mounted once in the signed-in App Shell. It reads the setting once per load (10 min stale, one transient retry) and falls back to 2/2 without a banner. A save updates the cache, so every open tab re-formats.
- Display: every money value and carat weight in Quotation, Reserve, Memo Receive / Return / Out / Out Return (tables, totals, summaries, From Stock and Memo Stock pickers, Memo Outstanding modal) and the Memo Outstanding From Vendor report, including its print view, uses the 0–4 places. Pieces, percentages and rates are unchanged.
- Typing: weight fields accept at most min(weight places, 3) and money fields at most min(price places, 2) (owner Q-DEC-08). This covers weight, Return weight, labor qty by weight, unit price, discount amount, labor rate and service charges. Auto-filled weights round the same way. Calculations and stored values are unchanged.
- Tests: frontend 63 files / 604 tests pass; `tsc --noEmit` 0 errors; ESLint 0 errors (2 existing warnings in `auth/login-form.tsx`). Live check through nginx: page save, 409 banner and Reload work, and QT-1001 at 3/0 shows `3.020 cts` and `430,533 THB`. The setting was restored to 2/2 (version 16).
