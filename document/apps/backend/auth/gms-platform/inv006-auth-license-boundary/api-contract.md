# API contract: auth-owned current license decision

- Source / SA revision: `INV-20261021-006-r1` / 1; approved for implementation (2026-10-21)
- Existing contracts: [auth GMS API revision 1](../api-contract.md), [ADR-0026](../../../../../adr/0026-gms-access-tokens-and-live-authorization.md), [ADR-0028](../../../../../adr/0028-gms-license-current-decision-order.md)
- Consumer: current partner process while hosting staged master tRPC; no browser consumer.

| Operation | Caller and input | Output | Authorization / compatibility |
|---|---|---|---|
| `POST /internal/v1/license/current` | `backend-api-partner` over the dedicated private network. `Authorization: Bearer <MASTER_AUTH_SERVICE_TOKEN>`. Strict JSON `{userId:string(1..128), sessionId:string(1..128)}`; reject extra keys, empty values and oversized body. | Eligible: `200 {decision:"ELIGIBLE", status:"VALID"|"EXPIRING"|"GRACE", checkedAt: ISO-8601 UTC, fallbackUntil: ISO-8601 UTC|null}`. No signed token, username or subject is returned. | Dedicated service credential plus auth-side verification that `(userId,sessionId)` exists in the current authorization view, account is active, and session is unexpired. Resolve license subject from auth `User.username`; never trust caller-supplied subject. No cache; no retries. Approved contract; implementation and runtime validation are in progress. |

Service credential is a 32-byte cryptographically random value encoded as 43-character base64url without padding. Infra mounts an out-of-repository file-backed Compose secret read-only at `/run/secrets/master_auth_service_token`; the only app setting is the non-secret path `MASTER_AUTH_SERVICE_TOKEN_FILE`. The backend reader trims at most one terminal LF/CRLF and rejects any other whitespace or extra line. Missing or unreadable secret disables/fails closed; the value is never accepted from an environment variable, request body, or command line. Auth performs the constant-time token check regardless of which network interface the request arrives on, because auth is multihomed and Docker bridges provide no source ACL.

Stable non-eligible responses use the existing `{error:{code,message,requestId}}` envelope: `401 SERVICE_UNAUTHENTICATED` for absent/invalid service token; `400 VALIDATION_ERROR` for malformed body; `401 AUTHORIZATION_CONTEXT_INVALID` if user/session is absent, mismatched, inactive or expired; `403 LICENSE_REQUIRED`, `LICENSE_EXPIRED`, or `LICENSE_REVOKED` for verified current denials; `503 LICENSE_UNVERIFIABLE` for license upstream unavailable without allowed grace, invalid token/proof, auth DB failure, timeout or internal dependency failure. Do not distinguish whether a user ID exists in the message. `Retry-After` may be supplied only for a known bounded transient condition; caller still does not retry automatically.

The caller deadline is 2,000 ms; auth endpoint's full handler deadline is 1,900 ms; upstream refresh deadline remains 1,500 ms per current client. No redirect, cookie forwarding, actor header, idempotency key, or client-controlled URL is accepted. Add `Cache-Control: private, no-store`; service tokens and license tokens must be excluded from access/request logs. `/internal/*` must return 404 at Nginx and is never configured as a public location. Existing auth license status/activation endpoints remain unchanged.
