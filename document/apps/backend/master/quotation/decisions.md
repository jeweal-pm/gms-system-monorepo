## Decisions (approve "SA quotation rev 1 as written", or name an ID / Q-QT to change)

| ID | Decision | Why |
|---|---|---|
| SA-QT-01 | **Owner and storage:** `backend-api-master`, schema `partner`, tables `quotation`, `quotation_line`, `quotation_charge`, `quotation_line_photo` ([database diagram](database-diagram.md)). | Same pattern as Document Setup; no new service on the 4 GB host (ADR-0032). |
| SA-QT-02 | **Permissions** (existing catalog leaf `quotation`, `MasterMenu` gains `quotation`): VIEW = list/get/options/next number/photo read; ADD = create + photo upload; EDIT = update + submit + photo upload; APPROVE = approve/reject; CANCEL = cancel; DELETE = delete. PRINT/EXCEL stay frontend-only (no output yet); PRICE is not enforced in rev 1 (Q-QT-07). | Uses the catalog as it is; no catalog change. |
| SA-QT-03 | **Status flow:** create → `DRAFT`. `submit` DRAFT/REJECTED → `PENDING_APPROVAL`. `approve` PENDING → `APPROVED`; `reject` PENDING → `REJECTED` (+ reason ≤ 500). `cancel` any non-cancelled → `CANCELLED` (+ reason). `update` only in DRAFT/REJECTED. `delete` only in DRAFT. A wrong state → `QUOTATION_STATUS_INVALID` (409). **Owner 2026-10-26 (Q-QT-02):** approving happens on the separate **Approve** page (built later), not on the Quotation page; the creator may approve their own quotation when they hold `quotation:APPROVE`. The backend ships `approve`/`reject` now for that page. | Matches the header stepper "Save → Pending Approval → Approve → Approved" and ADR-0025 D8. |
| SA-QT-04 | **Document number (owner 2026-10-26, Q-QT-03):** issued on create, in the same transaction. Pick the `quotation` numbering row with the latest `effective_date ≤ doc_date` and lock it (`SELECT … FROM document_numbering … FOR UPDATE`); running number = **highest `running_no` stored for that row + 1**, or its `start_no` when none; `doc_no = prefix + separator + running_no` (no padding, SA-DS-06). So deleting the latest quotation frees its number for the next save; a deleted number in the middle is not reused. **Amended by the owner 2026-10-26** ("ถ้าใน document setup ไม่ได้ set อะไรไว้ เลขรันนิ่งขอเป็น 1 2 3 ธรรมดาเลยจนกว่าจะมีการ set ใน document set up"): with no setup row in effect the number is plain `1, 2, 3 …` (highest plain number + 1 under a transaction advisory lock, `numbering_id` null, migration `20261026120000_quotation_plain_numbering`); `QUOTATION_NUMBERING_MISSING` is no longer used. `(numbering_id, running_no)` and `doc_no` are unique. The new form shows the next number from `quotation.nextNumber` as a preview; the saved number may be higher if someone saved first. | The row lock serializes concurrent saves; no separate counter to keep in sync. |
| SA-QT-05 | **Document Setup lock (Q-DS-06):** a numbering row referenced by any quotation is `used = true`; Document Setup save must keep used rows (same id, date, prefix, separator, start no), else `DOCUMENT_SETUP_ROW_IN_USE` (409). Save keeps row ids for rows it is given back. | Changing a used row would rewrite the meaning of issued numbers. |
| SA-QT-06 | **Header fields:** doc date, due date (required, ≥ doc date, chosen by the user — no default, Q-QT-08), customer (active, or the one already stored), shipping address (customer's SHIPPING), invoice address (customer's INVOICE), currency (runtime list), exchange rate (> 0, ≤ 6 dp; required when currency ≠ company currency), ref ≤ 100, document note ≤ 500. The server stores a **snapshot**: customer code + name and each address as formatted text. | Printed/approved documents must not change when masters change. |
| SA-QT-07 | **Lines** (1–200 filled lines; empty rows are not sent): `source` MANUAL only in rev 1 (STOCK reserved, rejected until inventory exists). Optional `stoneCodeId` (active `stone.stone_code`, or stored); attribute snapshot text (stone, shape, size, color, clarity, cutting, quality ≤ 60 each), lot ≤ 40, location ≤ 40, cert type ≤ 20, cert no ≤ 60 (free text: no masters yet, Q-QT-05), pcs integer 0–999,999, weight 0–99,999.999 ct (3 dp), price unit PER_CT/PER_PCS, unit price ≥ 0 (2 dp), item note ≤ 500, photos ≤ 4 (ordered; first = main). | Mirrors the form schema; bounds keep a save small. |
| SA-QT-08 | **Totals (server-authoritative):** ADR-0025 D5 formulas with `Prisma.Decimal`, half-up to 2 dp per stored amount: line amount; subtotal; discount (PERCENT 0–100 or AMOUNT ≤ subtotal); total after discount; tax (rate 0–100, include-in-price or added); service charges (fixed list SHIPPING, HANDLING, INSURANCE, CERTIFICATE, each once, amount ≥ 0); labor (work ≤ 120, basis PCS/WEIGHT, qty, rate); grand total. All amounts are in the document currency (Q-QT-01). Client-sent totals are ignored. | Money must not depend on browser floats. |
| SA-QT-09 | **Concurrency:** `version` int; update/submit/approve/reject/cancel/delete send `expectedVersion`; mismatch → `QUOTATION_CHANGED` (409). Update replaces lines, charges and line photos in one transaction. | Same as Company Profile / Document Setup. |
| SA-QT-10 | **Photos:** `POST /api/v1/quotation/photos` (raw body, `image/jpeg` or `image/png`, magic-byte check, ≤ 5 MB) → `{photoId}`; stored via `@gms/storage` module `quotation-photo`, metadata in `partner.stored_file` (source `quotation.line-photo`). A line references photo ids; an id that is not a quotation photo → `QUOTATION_PHOTO_INVALID`. `GET /api/v1/quotation/photos/:id` streams it to VIEW users. Unlinked uploads and replaced photos are kept (ADR-0030); no purge. | Reuses the approved storage profile. |
| SA-QT-11 | **Lists:** `quotation.list` keyset on `(doc_date desc, created_at desc, id desc)`, ≤ 50 rows, filters status/customer/date range, search doc no / customer name / ref (≤ 100 chars). Cancelled quotations are excluded unless `status: "CANCELLED"` is asked for. Daybook on the Quotation page = this list, newest first, no cancelled (owner 2026-10-26, Q-QT-06). `quotation.options` returns active customers with their addresses and currencies in one call (≤ 1,000 customers). | Bounded queries (ADR-0024 capacity). |
| SA-QT-12 | **Errors and audit:** domain codes in [api-contract.md](api-contract.md#errors); `created_by/updated_by/approved_by/approved_at/cancelled_*` columns; structured log events `quotation.created/updated/submitted/approved/rejected/cancelled/deleted` (ids only, no prices or customer data). | Same envelope as other master features. |
| SA-QT-13 | **Frontend scope:** replace `api.ts` mock calls with typed `masterTrpc.quotation.*`; options and the next-number preview from the API; header actions Save / Edit / Send for Approval / Delete by permission and status (owner 2026-10-26: no Cancel Quotation button on this page; `quotation.cancel` stays in the API) — **no Approve/Reject on this page** (SA-QT-03); due date starts empty; From Stock button disabled with "Stock isn't available yet"; Print/Excel stay disabled; Document Setup page shows used rows locked. | No UI redesign; contract swap behind `api.ts` as ADR-0025 planned. |
| SA-QT-14 | **Infra:** add one nginx location `/api/v1/quotation/photos` → `api-master` (dev `docker/nginx/gms-dev.conf` and the production profile), body limit 5 MB. No other container/volume change; photos use the existing master storage mount. | Binary upload cannot go through tRPC JSON. |

## Correction 2026-10-26 — no approval for quotations

**Corrected by the owner 2026-10-26** ("ลบปุ่ม send of approval ไปเลยบอกเเล้วว่า quotation ไม่มี approve"): Quotation has **no approval step**. Quotations stay `DRAFT` (editable and deletable by permission); the Quotation page has no Send for Approval / Approve / Reject / Cancel buttons. The `submit`/`approve`/`reject`/`cancel` procedures remain in the API but are not used by the UI.
