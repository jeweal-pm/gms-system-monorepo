## Domain and service boundaries

Reuse staged master customer/vendor tRPC router, JWT verifier, auth-owned current-authorization view, grant checks, customer/vendor services and current partner schema. Auth remains the only owner of license subject resolution, current remote/mock license call, and the ordered decision table. Master gets only a minimal decision state, never a signed license token or auth base-table access. No new package, schema object, table, container or service identity is proposed in this delta.

The proposal adds an auth-owned private endpoint and exact role contract, then mounts the existing master router at `/api/master/trpc` with a request context factory. Its public browser call is protected by user JWT, exact current auth view, current license response, current grant and CSRF enforcement. This does not authorize route parity completion, Nginx/config edits, `api-master` rename, gateway removal or deployment.

## Behavior and operation

The context factory MUST reject mutation CSRF before any authorization/license lookup or domain service invocation. Determine method and verify exact trusted `Origin`, `X-GMS-CSRF: 1`, and `Sec-Fetch-Site` absent or `same-origin`/`same-site`; reject failure immediately. Then validate the user JWT, query the auth view by `(sub,sid)` using a **separate** `MASTER_AUTHZ_DATABASE_URL` reader client, call auth's private current-license endpoint, and construct the context. When master auth is enabled, missing or invalid `MASTER_AUTHZ_DATABASE_URL` fails closed at startup; there is no fallback to `PARTNER_DATABASE_URL`. Existing `PARTNER_DATABASE_URL` and Prisma client remain responsible for partner/stone owned-schema procedures, including legacy company-profile/stone routes still running in this process. Do not change those credentials or broaden the reader role to serve domain writes. tRPC procedure middleware checks grant and input before invoking a domain service. All missing/mismatched/unavailable proofs stop before the domain service. Reuse current customer/vendor schemas and <=200 list bound.

Mount only the currently staged customer/vendor router, with no unstaged company-profile/stone procedures. Keep same-origin Nginx `/api/master/trpc` as public route; Nginx must deny `/internal/*`. The existing `ServiceTokenGuard` must not accidentally require the internal token for the browser tRPC path; make only the tRPC route explicitly public to that service-token guard while it remains protected by the user-auth context. Existing internal partner REST routes remain service-token-only. Do not trust user, role, permission, license or actor fields from browser headers/body except validated master procedure input.

Use the [private endpoint contract](../../../auth/gms-platform/inv006-auth-license-boundary/api-contract.md), 2,000 ms license-call deadline, no retries/cache. Keep mutation response behavior and tRPC error mapping compatible with the old gateway. Login/session JWT and local grant rules stay unchanged. License state follows ADR-0026/0028 and the endpoint returns only `ELIGIBLE` or stable denial/unavailable outcomes.

## Capacity, rollout and rollback

No process/container or package addition. Preserve existing partner limit 384 MiB/0.25 vCPU. Keep the existing partner pool bounded at <=5 and add a separate read-only master-authz pool of <=1 connection. This stays inside the accepted target master pool allowance of 10 (ADR-0025); count the reader explicitly rather than increasing the total pool. The auth client call is sequential once per request and timeout bounded; no fan-out or queue. Across the current 1.70 vCPU / 2944 MiB aggregate, this adds work inside existing caps and does not prove the target GMS profile's 4 GB/2 vCPU fit. Measure cold JWKS and warm path latency, request p95, failure-path latency, DB pool saturation and process RSS before cutover.

Rollout order: (1) infra approves the private network/port topology and secret injection, (2) backend provisions the dedicated auth-reader role/grant and supplies `MASTER_AUTHZ_DATABASE_URL` independently, (3) auth endpoint is implemented/tested using mock-only local configuration, (4) master context and mounted route are implemented/tested, (5) negative/positive HTTP and DB privilege tests pass and both focused security reviews pass same source revision, (6) parent performs feature parity and explicit rollout decision. Rollback immediately unmounts the new tRPC route and restores legacy Next/gateway routing; revoke private token and disable/revoke only the dedicated reader login/grants while retaining existing partner credential, schema/data and additive auth state. No container deployment or service rename is included.
