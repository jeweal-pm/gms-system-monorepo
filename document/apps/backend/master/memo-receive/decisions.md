| SA-MR-04 | Stock ID: `YY ‖ lpad(n,4,'0')`, where `YY` is the **year of the save** (server clock, Asia/Bangkok; owner Q-MR-08 2026-10-29), not the Doc Date. `n` comes from `memo_stock_id_counter(year)` (`INSERT … ON CONFLICT DO UPDATE SET last_no = last_no + k RETURNING`, row lock inside the save transaction). Assigned on create, and on update to lines without `id`, using the year of that save. Lines sent with their `id` keep their Stock ID. Numbers of removed lines are not reused. `n > 9999` → `MEMO_RECEIVE_STOCK_ID_EXHAUSTED` (409). The owner expects fewer than 9,999 a year, and the final rule stays open (Q-MR-09). Unique on `memo_receive_line.stock_id` and `memo_stock.stock_id`. |

Log `memo_receive.approved` (id, docNo, line count). |
| SA-MR-06 | Memo Stock row: `location = 'Memo'` (CHECK), `received_pcs/weight_ct` = line values, `pending_pcs/weight_ct` = same (CHECK 0 ≤ pending ≤ received), vendor id + code/name snapshot, currency, price unit, gross `unit_price`, the line net `line_amount` (after the line discount) and `net_unit_price` = `line_amount` ÷ received basis (weight for CTS, pcs for PCS), 4 dp half-up (owner Q-MR-13 2026-10-29: **price after discount**). A document-level discount is not spread over items., stone attributes, lot, cer, item note, memo receive id/line id/doc no/doc date/due date. Memo Return (later revision) is the only writer of `pending_*`. |
| SA-MR-07 | Location removed from Memo Receive input and UI; shown as `Memo` from `memo_stock.location` in "Add Memo Stock" and future "From Stock". |
| SA-MR-08 | Numbers: Document Setup key `memo-receive` (exists, code `MR`); `NumberedDocument` gains `memoReceive` (`partner.memo_receive.plain_running_no` advisory key); Document Setup `used` also counts `memo_receive`. `nextNumber` previews. |
| SA-MR-09 | Party, header, lines, totals as Memo Out Return (SA-MO-05/06): active vendor + one of its addresses, snapshots; currency active or stored; exchange rate for foreign currency; ≤ 200 lines; server totals with the quotation calculator, line % ≤ 100, line amount discount ≤ line gross, document amount discount ≤ subtotal (fixes the FE-MR-006 advisory: totals never negative). `photoIds` max 0. |
| SA-MR-10 | Options: `memoReceive.options {vendorId?}` = `memoOutReturn.options` shape (vendors + addresses, currencies, company currency, charge types, numbering, stone lists, without stone codes). Gated by `memo-receive:VIEW` only — replaces the four separate master reads (ADR-0033 frontend advisory). |
| SA-MR-11 | `memoStock.list`: `{vendorId, q?, from?, to?, cursor?, limit ≤ 50}`; rows with `pending_pcs > 0 OR pending_weight_ct > 0`; `q` ILIKE on stock id, lot, stone, cer no, memo receive doc no (escaped, ≤ 100 chars); date range on memo receive doc date; keyset `(received_doc_date desc, stock_id desc)`; price shown = `net_unit_price`. Amount = `line_amount` × pending basis ÷ received basis (Cts → weight, Pcs → pcs), half-up 2 dp, so a fully pending item shows exactly its line amount. Permission `memo-return:VIEW` or `memo-receive:VIEW`. |
| SA-MR-12 | Errors `MEMO_RECEIVE_*` (see [error-handling](error-handling.md)); logs ids/doc no only, never prices or vendor names. |

## SA revision 2 (2026-10-29): line photos — **approved** (Owner 2026-10-29: "อนุมัติ memo-receive revision 4")

Owner request 2026-10-29 (verbatim): "ทำให้เพิ่มรูปได้เลยได้ไหม" (screenshot: row panel "Photos 0 / 5" showing "Photos for this document come in a later update"). This revision lifts the "no photos" limit of SA-MR-09/13 and copies the approved Quotation photo design (SA-QT-10/14, ADR-0029/0030, INV-20261026-001 bounds).

| ID | Decision |
|---|---|
| SA-MR-14 | Table `memo_receive_line_photo (line_id FK → memo_receive_line CASCADE, position 1..5, file_id FK → stored_file RESTRICT, PK (line_id, position))`, migration `20261029150000_memo_receive_line_photo` (additive). |
| SA-MR-15 | `POST /api/v1/memo-receive/photos`: raw body `image/jpeg`/`image/png`, ≤ 5 MB, magic bytes must match. Stored via `@gms/storage` module `memo-receive-photo`, metadata in `partner.stored_file` with source `memo_receive.line-photo`. Returns `201 {photoId}`. `GET /api/v1/memo-receive/photos/:id` streams the image. Both routes reuse the Quotation photo HTTP code. The **same process-wide limiter** (3 uploads, 6 downloads at a time) is shared with Quotation, so the host bound does not grow. |
| SA-MR-16 | Grants: upload needs `memo-receive:ADD` or `EDIT` + CSRF; read needs `memo-receive:VIEW`. A photo of another module (for example a quotation photo id) → `MEMO_RECEIVE_PHOTO_INVALID` (422, `lines.N.photoIds.M`). |
| SA-MR-17 | Line input `photoIds` allows up to 5 distinct ids in order; the first is the main photo. Create and update replace each line's photo links in the save transaction. A line that keeps its `id` keeps only the photos it sends. Once the document is APPROVED its photos are read-only, like the document. Uploaded bytes are kept permanently, including unlinked and replaced photos (ADR-0030). |
| SA-MR-18 | Memo Stock does not copy photos. Later readers (the Memo Return dialog) reach them through `memo_stock.memo_receive_line_id`. That read is not in this revision. |
| SA-MR-19 | Infra: one nginx location `^~ /api/v1/memo-receive/photos` → `api-master:3201`, `client_max_body_size 6m`, in `docker/nginx/gms-dev.conf`. That file is integration-owned, so the parent makes the edit. No new container, volume, image or package. Photos use the existing master storage mount. |
