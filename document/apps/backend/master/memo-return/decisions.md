# SA decisions: memo-receive API + memo-return, SA revision 1 (2026-10-29)

- Features: `memo-return` (UI rev 1, [ui-spec](../../../frontend/memo-return/ui-spec.md)). The `memo-receive` API is the Memo Stock source; its page stays the [mock](../../../../adr/0033-memo-receive-frontend-mock.md) for now.
- Status: **implemented**. Owner 2026-10-29: "uxui ช่วยเขียน spec memo return ให้หน่อยและ frontend backend ช่วยเขียน UI และ api ให้หน่อย Memo Return No.: ดึงค่ามาจาก Document set up ด้วย". Source answer the same day: Memo Stock comes from **Memo Receive**, with the API built first (backend only).
- Builds on [ADR-0033](../../../../adr/0033-memo-documents-in-master-service.md) (memo documents in `backend-api-master`, shared engine) and the [memo-out SA rev 1](../memo-out/decisions.md) rules. Contract: [api-contract.md](api-contract.md).
- Service: `backend-api-master`, schema `partner`. No new service, container, volume, nginx route or package.

| ID | Decision |
|---|---|
| SA-MR-01 | Migration `20261029090000_memo_receive_return` adds six tables: `memo_receive`, `memo_receive_line`, `memo_receive_charge`, `memo_return`, `memo_return_line`, `memo_return_charge`. Same columns and CHECKs as memo out return. `memo_return_line` adds `source_line_id` (FK → `memo_receive_line`, ON DELETE RESTRICT, indexed) and `outstanding_pcs` / `outstanding_weight_ct`, with CHECK pcs ≤ outstanding_pcs and weight ≤ outstanding_weight. Dev only: the empty orphan `memo_receive*` tables of a lost earlier attempt (migration `20261026170000_memo_receive`, never in git) were dropped with their migration record before applying. |
| SA-MR-02 | Permissions: existing leaves `memo-receive` / `memo-return` (VIEW / ADD / EDIT / DELETE as SA-MO-02). `memoReturn.memoStock` needs `memo-return:VIEW`. `currency.options` is readable with either leaf. |
| SA-MR-03 | Numbers come from Document Setup keys `memo-receive` (MR) and `memo-return` (MRT), with the same rules as SA-MO-04. Document Setup `used` now also counts memo receive and memo return documents. |
| SA-MR-04 | Party: vendor + one of its addresses (shared `vendorParty` adapter, also used by memo out return). Drafts only, no photos, no stock posting. |
| SA-MR-05 | **Memo Stock** = memo receive lines of the return's vendor **and currency** with pending > 0 (pcs or weight). Pending = line pcs / weight − the sum already returned by other memo returns. `memoStock` returns ≤ 200 rows, newest receipt first, filtered by receive date (`from` / `to`) and search (stone code, stone, lot, location, receive no.), leaving out an edited return's own lines (`excludeReturnId`). |
| SA-MR-06 | Saving a memo return completes its lines inside the write transaction (engine `prepare` hook). It locks the named memo receive lines (`FOR UPDATE`, id order) so concurrent returns can't take the same quantity. It checks each line belongs to the vendor and currency (else `MEMO_RETURN_REFERENCE_INVALID`, `lines.N.sourceLineId`); a line used twice → `VALIDATION_ERROR` `duplicate`. It copies the item fields and price from the source and stores Outstanding = pending. Return pcs / weight > pending → `VALIDATION_ERROR` `exceeds_outstanding`. The client sends only the source line, the Return quantity and the item note that matter; other line fields are overwritten. |
| SA-MR-07 | A memo receive with any returned line can't be edited or deleted: `MEMO_RECEIVE_IN_USE` (409), engine `writeGuard` hook. Its line ids stay stable while no return points at them. |
| SA-MR-08 | Not in revision 1: memo receive Stock IDs (the mock page numbers them; Q-MRT-05), its approval flow (the mock has Pending approval / Approved, the API drafts only), photos, and the Memo Receive page on the API. |
