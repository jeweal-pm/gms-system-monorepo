| ID | Decision |
|---|---|
| SA-MOR-11 | **Party = customer** (Q-MOR-11, owner 2026-10-31; replaces the vendor answer Q-MOR-02) with a **Shipping and an Invoice address** of that customer, exactly as Memo Out (Q-MOR-12): the Memo Out customer adapter is reused (inactive customer only when already stored; each address must belong to the customer and have its kind). `memoOutReturn.options` lists customers with addresses, the `memoOut.options` shape. |
| SA-MOR-12 | **Status**: `PENDING_APPROVAL` → `APPROVED` (Q-MOR-14, replaces Q-MOR-07 "Draft only"). It uses the same engine config as Memo Out / Memo Return (`createStatus`, `editableStatuses`). `memoOutReturn.approve {id, expectedVersion}` needs `memo-out-return:APPROVE` + CSRF. Edit and delete only while pending. No reject or unapprove. |
| SA-MOR-13 | **Lines come only from Memo Outstanding.** Each line names one approved Memo Out line (`memoOutLineId`) of the document's customer and currency (Q-MOR-15). One return may take lines from several Memo Outs (Q-MOR-03). The same Memo Out line may appear at most once per return. Every Memo Out line is a stock line since memo-out revision 3 (Q-MOR-13); a manual line stored before it is not listed and is rejected on save. There is no Add row and no manual return line. |
| SA-MOR-14 | **Outstanding per Memo Out line.** New counters `memo_out_line.returned_pcs` / `returned_weight_ct` (default 0, CHECK 0 ≤ returned ≤ pcs / weight). Outstanding = pcs − returned_pcs and weight_ct − returned_weight_ct. Only approval of a Memo Out Return writes them. Only stock lines get returns, so the counters of manual lines stay 0. |
| SA-MOR-15 | **Memo Outstanding picker** `memoOutReturn.outstanding`: approved Memo Out **stock** lines of the customer (and currency) with outstanding pcs or weight > 0, newest Memo Out first. It uses a keyset of up to 50 rows, with search (Memo Out No., Stock ID, lot, stone, cer no.) and a Memo Out doc-date range ≤ 366 days. It can leave out lines already in the return being edited (`excludeReturnId`). Price = the Memo Out line's net unit price (after its line discount, 2 dp). Amount = price × outstanding basis. |
| SA-MOR-16 | **Saving** (engine `prepare`, no lock, reserves nothing): it validates the line references (`MEMO_OUT_RETURN_REFERENCE_INVALID lines.N.memoOutLineId`: missing, not approved, manual line, other customer or currency) and `duplicate`. It copies the item fields, Stock ID / lot, price unit and price from the Memo Out line, and stores Outstanding = outstanding now. Return pcs / weight above that → `VALIDATION_ERROR exceeds_outstanding`. Pcs or weight must be > 0. |
| SA-MOR-17 | **Approve** (one `WRITE_TX`, the Memo Return pattern):<br>1. Guarded status UPDATE.<br>2. Lock the Memo Out lines `FOR UPDATE` in id order and re-check outstanding, else `MEMO_OUT_RETURN_OUTSTANDING_SHORT` (409, short line fields) and nothing changes.<br>3. `memo_out_line.returned_* += q`.<br>4. Lock those `memo_stock` rows in id order and move `reserved_* −= q`, `pending_* += q`, version + 1 (Q-MOR-16). `memo_stock_balance` holds, and the item is available again for From Stock and Memo Return.<br>Q-MOR-14 (owner 2026-10-31): stock comes back only here, never on save. Log `memo_out_return.approved` (id, docNo, line count). |
| SA-MOR-18 | **Migration `20261101090000_memo_out_return_customer`**, guarded: it **aborts if any `memo_out_return` row exists** (Q-MOR-17; dev has none). It replaces `vendor_id` / `vendor_*_snapshot` / `address_id` / `address_snapshot` with `customer_id` (FK customer RESTRICT), `customer_code_snapshot`, `customer_name_snapshot`, `shipping_address_id` / `invoice_address_id` (FK customer_address SET NULL) and `shipping_address_snapshot` / `invoice_address_snapshot`, as memo_out. It adds the status CHECK `PENDING_APPROVAL | APPROVED`, `approved_at` / `approved_by` with their CHECK, `memo_out_return_line.memo_out_line_id` (NOT NULL, FK RESTRICT, indexed, unique per return) and the `memo_out_line.returned_*` counters + CHECK. It adds partial index `memo_out_line_open_idx (memo_out_id) WHERE memo_stock_id IS NOT NULL AND (returned_pcs < pcs OR returned_weight_ct < weight_ct)`. Rollback while no memo out return is approved: reverse each step. |
| SA-MOR-19 | **Memo Out stays consistent.** A Memo Out with any returned line can't be edited or deleted: it is already approved, so the existing rule covers it. The Memo Outstanding › Vendor report needs no change, because Reserve already falls when items come back. |
| SA-MOR-20 | **Not in this revision:** our own stock (inventory), the Memo Outstanding › Customer report page, reversing an approved return, line photos, Due Date rules beyond due ≥ doc date (Q-MOR-09/18). |

Capacity: approval locks ≤ 200 Memo Out lines and ≤ 200 Memo Stock rows in one transaction, with 2 batch UPDATEs. The picker is 1 query, ≤ 51 rows, on the partial index and `memo_out_customer_idx`. The pool, container limits and the 4 GB host budget are unchanged.
