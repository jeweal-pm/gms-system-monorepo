## Decisions (SA-MS-nn)

| ID | Decision |
|---|---|
| SA-MS-01 | **Placement:** `backend-api-inventory`, module `src/modules/merge-split/` (ADR-0052 D1). Stock writes only through new `src/modules/stock/convert.ts` (`applyConversion`, `reverseConversion`). |
| SA-MS-02 | **Tables:** `merge_split`, `merge_split_source`, `merge_split_result`, `merge_split_result_photo` ([database-diagram](database-diagram.md)). One `mode` per document: `SPLIT` or `MERGE` (no None, Q-MS-03). |
| SA-MS-03 | **Conservation (Q-MS-04):** source take = its on hand snapshot (whole). SPLIT: 1–200 sources, each with ≥ 2 results, Σ result pcs = take pcs and Σ weight = take weight per source. MERGE: 2–200 sources, exactly 1 result = Σ. Result pcs ≥ 1; result weight > 0 unless the take weight is 0. ≤ 200 results per document. |
| SA-MS-04 | **Availability (Q-MS-02/15):** usable = `on_hand` only. Picker hides stocks on another `PENDING_APPROVAL` document; submit refuses them (`409 MERGE_SPLIT_SOURCE_PENDING`). Apply locks sources `FOR UPDATE ORDER BY id` and requires ACTIVE, own, load not SYNCING, on hand = snapshot; else `409 MERGE_SPLIT_STOCK_CHANGED` (current values) / `409 MERGE_SPLIT_BUSY` (Retry-After 5). |
| SA-MS-05 | **Cost:** take cost = `sourceAmount(price_unit, take pcs, take weight, unit_cost_base)` (reuse `load-to-stock/cost.ts`). SPLIT result: source price unit and unit cost; cost = basis × unit cost (2 dp); last result (highest position) of each source takes the residue. MERGE result: `rowPriceUnit("MERGE", units)`, cost = Σ take cost, unit = `rowUnitCost`. Client-sent cost is never trusted. |
| SA-MS-06 | **Result details:** stone code/attributes, grading, cer, lot, location, parcel, stock price, sale price, item note, photos are input (Q-MS-06/07/10). Validated before the transaction with the existing master `master-data/resolve` (stone code ids + location names). Inherited from the source (SPLIT) or the oldest source by `(ref_doc_date, stock_id)` (MERGE): `currency_code`, `vendor_id`, `vendor_name_snapshot`, `load_id`, `ref_doc_date`, `ref_doc_no`. MERGE sources with different `currency_code` → `422 MERGE_SPLIT_CURRENCY_MIXED`. |
| SA-MS-07 | **Stock IDs:** master `POST /internal/v1/inventory/stock-ids/issue {documentType:"merge-split", documentId, applySeq, count ≤ 200}` → `{ stockIds }`, under the existing `STOCK_ID_LOCK_KEY` and `issueStockIds`; idempotent through `partner.inventory_stock_id_issue` (same key + same count replays, different count → 409 `STOCK_ID_ISSUE_CONFLICT`). Called before the inventory transaction; `applySeq` = `merge_split.apply_seq + 1`. Gaps from abandoned issues are allowed. |
| SA-MS-08 | **Apply** (`applyConversion`, one transaction, ≈ 8 statements): lock doc (version) → lock sources → checks → one `UPDATE stock … FROM (VALUES …)` (`on_hand −= take`, `consumed += take`, `first_used_at`, `version + 1`) → `createMany` result stocks (status ACTIVE, `pcs = on_hand`), `stock_photo`, `stock_movement` (OUT per source, IN per result) → one UPDATE of results (`stock_uuid`, `stock_id`, `applied_version = 1`) and sources (`take_cost_base`) → doc APPROVED, `apply_seq + 1`, `applied_at`. |
| SA-MS-09 | **Ledger kinds:** `SPLIT_OUT`, `SPLIT_IN`, `SPLIT_REVERSAL`, `MERGE_OUT`, `MERGE_IN`, `MERGE_REVERSAL` (≤ 20 chars). `document_type = 'merge-split'`, `revision = apply_seq`. Cost delta: OUT `−take_cost`, IN `+result cost`. |
| SA-MS-10 | **Stock Card / Value:** six `CARD_KINDS` rows (`merge-split`, MOVEMENT); `DOCUMENT_TYPES["merge-split"] = { label: "Merge/Split", stockIdVisible: true, source: "MERGE_SPLIT" }`; `card.ts` `dated` CTE joins `merge_split` for doc date/no (account name `''`). No card key on movements: existing rows never change card ([architecture](architecture.md#card-keys)). Stock Value: no code change. |
| SA-MS-11 | **Reverse** (`reverseConversion`): lock results and sources in one id-ordered lock; every result must be ACTIVE with `version = applied_version` else `409 MERGE_SPLIT_IN_USE {stockIds}`. Results → REVERSED (as `reverseStocks`), sources `on_hand += take`, `consumed −= take`, `version + 1`, `*_REVERSAL` rows. Used by delete of an effective doc and by edit of an auto-approved doc (reverse, then re-apply with new Stock IDs). |
| SA-MS-12 | **Approval** (ADR-0050, ADR-0052 D8): type `merge-split` already exists in `INVENTORY_APPROVAL_TYPES` and the DB check/seed. Add it to `/approval/summary`, `/approval/pending` and the turn-OFF waiting count. OFF → Save applies (APPROVED, `auto_approved`). ON → DRAFT → submit → PENDING → approve applies; revise once; reject final. Edit is allowed in DRAFT/REVISION and for auto-approved effective documents (SA-MS-11); not for approver-approved ones (delete only). |
| SA-MS-13 | **Numbering:** key `merge-split` (code MS exists in Document Setup) added to master `INVENTORY_NUMBERING_KEYS` and inventory `NumberingKey`; number issued on first Save. |
| SA-MS-14 | **From Stock read:** `GET /merge-split/stock` over `stock` (own, ACTIVE, on hand > 0 via `stock_picker_idx`), filters `location`, `q`, `exclude` ≤ 200, `NOT EXISTS` a `merge_split_source` on another PENDING document (`excludeDocId` = current doc). Keyset `(ref_doc_date, stock_id, id)`, ≤ 50, one statement. Returns Stock ID (Q-MS-01). |
| SA-MS-15 | **Photos:** results reference `stored_file` ids. `GET /merge-split/stock/{stockUuid}/photos` returns the source's file ids (relink, no byte copy). `POST /merge-split/photos` uploads JPEG/PNG ≤ 5 MiB to `files/merge-split/` (`source_type` `merge-split.result-photo`) by generalizing `load-to-stock/photos.ts` helpers (module + source parameters). `GET /merge-split/photos/{fileId}` streams a file linked to a merge-split result or an own stock. No delete API (bytes kept, SA skill rule). |
| SA-MS-16 | **Permissions:** leaf `merge-split` (exists, no auth migration); VIEW / ADD / EDIT / DELETE / APPROVE ([authorization](authorization.md)). |
| SA-MS-17 | **Bounds:** ≤ 200 sources, ≤ 200 results, ≤ 5 photos per result, JSON ≤ 256 KiB, picker ≤ 50, fixed statements per apply/reverse, no HTTP inside a transaction, existing `WRITE_TX` timeout. |

## SA questions (SQ-MS-nn): defaults proposed

| ID | Question | Default |
|---|---|---|
| SQ-MS-01 | New stock's `ref_doc_date`/`ref_doc_no`/`load_id`: inherit or use the MS document? | **Inherit** from the source (Merge: oldest source) so FIFO age and the Load link stay; the MS link is on Stock Card and on `merge_split_result`. |
| SQ-MS-02 | Merge sources with different currency | **Refused** (`MERGE_SPLIT_CURRENCY_MIXED`); cost is company currency, but stock/sale prices are in the stock currency. |
| SQ-MS-03 | Edit of an auto-approved effective document | **Reverse + re-apply**; results get new Stock IDs (old ones retired). Approver-approved: delete only. |
| SQ-MS-04 | Vendor of a merged stock | The oldest source's vendor (same rule as SQ-MS-01). |
| SQ-MS-05 | Stock IDs issued for an apply that never commits | **Gap allowed**; a retry with the same `applySeq` reuses them. |
| SQ-MS-06 | Notifications (bell) for submit/approve | Same events as Stock Adjustment (`documentType: "merge-split"`). |
